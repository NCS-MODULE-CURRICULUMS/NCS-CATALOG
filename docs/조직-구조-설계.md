# NCS-MODULE-CURRICULUMS — 조직 구조 설계

NCS 기반 IT 교육 커리큘럼 저장소 조직의 전체 구조 문서입니다.

## Repo 구성

| Repo | 공개 | 역할 | 오너 |
|---|---|---|---|
| `NCS-CATALOG` | **public** | NCS 원천 데이터 + 수집 스크립트 + 도메인 매핑. **조직의 SSOT** | 전체 |
| `CURRICULUM-WEB-APP` | private | 웹앱/풀스택 교안 (세분류 4 / 능력단위 61) | — |
| `CURRICULUM-SECURITY` | private | 정보보안 교안 (세분류 9 / 능력단위 75) | — |
| `CURRICULUM-CLOUD-INFRA` | private | 클라우드·인프라·DevOps 교안 (세분류 5 / 능력단위 52) | — |
| `CURRICULUM-AI-DATA` | private | AI·ML/DL·데이터 교안 (세분류 10 / 능력단위 94) | — |
| `COURSE-*` | private | 실제 운영 과정 편성(회차별). 커리큘럼을 **참조만** 함 | 과정별 |
| `.github` | public | 조직 프로필 README, 공용 워크플로/템플릿 | — |

## 설계 원칙 3가지

1. **폴더명 = NCS 코드** — `20010707_생성형AI엔지니어링/05_프롬프트 구현/`
   코드가 1급 키라서 검색·정렬·자동검증이 전부 여기서 나옵니다.
2. **front-matter로 검증** — 모든 `teaching-plan.md`의 `unit_code`를
   `NCS-CATALOG/data/competency-units.csv`와 CI에서 대조. 폐지된 능력단위 자동 검출.
3. **COURSE-*는 복사하지 않는다** — submodule 또는 `curriculum.lock.yml`(repo + commit SHA)로 참조.
   회차 종료 시 `v2026-1` 태그.

## 왜 도메인 4개인가

- 세분류마다 repo(20개+)를 만들면: 웹앱 과정 하나가 `응용SW + UI/UX + DB + SW아키텍처` 4개 repo를 동시에 건드림 → 교차참조 지옥
- mono-repo 하나면: 강사·기관별 권한 분리와 부분 공개가 불가능
- 도메인 4개 = 강사 1인이 한 repo를 온전히 소유할 수 있는 크기
